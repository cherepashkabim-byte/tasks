# Задачи — мини-приложение в Telegram

Личный список задач, который открывается кнопкой в твоём Telegram-боте.
Задачи раскладываются по **проектам** (с эмодзи и шкалой прогресса в процентах — с мотивацией и салютом, когда проект закрыт) и помечаются **темами** — цветными метками,
которые проходят через все проекты. Главный экран «Сроки» показывает, что просрочено, что на сегодня, на завтра и дальше.

Данные хранятся в облаке Telegram (CloudStorage) и видны только тебе — на всех твоих устройствах.
Сервер не нужен: приложение — это обычная страница, которую бесплатно раздаёт GitHub Pages.

> **Токен бота приложению не нужен.** Когда @BotFather выдаст тебе токен, его никуда не надо вставлять —
> ни в код, ни в настройки GitHub. Просто сохрани его у себя и никому не показывай.

Ниже — путь от нуля до кнопки в боте. Делай шаги по порядку.

---

## Шаг 1. Установи программы (один раз)

1. **Node.js** — скачай версию «LTS» с [nodejs.org](https://nodejs.org) и установи, нажимая «Далее».
2. **Git** — скачай с [git-scm.com](https://git-scm.com/downloads) и установи с настройками по умолчанию.
3. Зарегистрируйся на [github.com](https://github.com), если ещё нет аккаунта.

Проверка: открой «Терминал» (на Windows — PowerShell) и введи по очереди:

```
node -v
git --version
```

Если в ответ появились номера версий — всё установлено.

## Шаг 2. Запусти приложение у себя на компьютере

1. Открой терминал **в папке проекта** (в Проводнике Windows: зайди в папку, кликни по адресной строке,
   напиши `powershell` и нажми Enter).
2. Установи зависимости (нужно один раз, займёт минуту):

   ```
   npm install
   ```

3. Запусти:

   ```
   npm run dev
   ```

4. Терминал покажет адрес вроде `http://localhost:5173` — открой его в браузере.
   Внизу будет плашка «Открыто вне Telegram — данные только в этом браузере» — это нормально:
   в браузере задачи хранятся только в нём, а облако Telegram включится, когда откроешь приложение из бота.
5. Остановить: вернись в терминал и нажми `Ctrl + C`.

Проверить, что всё собирается без ошибок, можно командами `npm test` и `npm run build`.

## Шаг 3. Создай репозиторий на GitHub и сразу включи Pages

Порядок важен: Pages включаем **до** первой загрузки кода, иначе первый запуск выкладки будет красным.

1. На github.com нажми **«+»** в правом верхнем углу → **New repository**.
2. Придумай имя (например, `tasks`), выбери **Public** и нажми **Create repository**.
   Ничего не добавляй (ни README, ни .gitignore) — они уже есть.
3. В новом репозитории открой вкладку **Settings** → слева **Pages**.
4. В разделе **Build and deployment** в поле **Source** выбери **GitHub Actions**. Сохранять ничего не нужно —
   выбор применяется сразу.

## Шаг 4. Загрузи код — приложение выложится само

1. В терминале, в папке проекта, выполни по очереди (подставь свой логин и имя репозитория вместо
   `<твой-логин>/<имя-репозитория>`):

   ```
   git init
   git add .
   git commit -m "Первая версия"
   git branch -M main
   git remote add origin https://github.com/<твой-логин>/<имя-репозитория>.git
   git push -u origin main
   ```

   Если проект уже был под Git, `git init` ничего не сломает, а `git commit` может ответить «nothing to commit» — это нормально, иди дальше.
   Если Git спросит имя и почту — выполни
   `git config --global user.name "Твоё имя"` и `git config --global user.email "почта@пример.ру"`, затем повтори `git commit`.
   При первом `git push` откроется окно входа в GitHub — войди.
2. Открой на github.com вкладку **Actions**. Там уже идёт «Deploy to GitHub Pages» — подожди 1–2 минуты,
   пока появится зелёная галочка.
   **Если первый запуск всё же красный** (например, Pages включился с задержкой) — это не поломка:
   проверь, что в **Settings → Pages** стоит **GitHub Actions**, открой красный запуск и нажми **Re-run all jobs**.
3. Адрес приложения будет таким:

   ```
   https://<твой-логин>.github.io/<имя-репозитория>/
   ```

   Он также виден в **Settings → Pages** и в результате запуска на вкладке **Actions**. Открой его в браузере — должно работать.

Дальше всё автоматически: каждый `git push` в ветку `main` заново собирает и выкладывает приложение.
Если отправить несколько push подряд, выкладки встанут в очередь и пройдут по порядку.

## Шаг 5. Создай бота в @BotFather

1. В Telegram найди **@BotFather** (с синей галочкой) и нажми **Start**.
2. Отправь `/newbot`.
3. Введи имя бота (как он будет подписан, например «Мои задачи»).
4. Введи username — латиницей, обязательно с окончанием `bot` (например `my_tasks_123_bot`).
5. BotFather пришлёт поздравление и токен. **Токен этому приложению не нужен** — никуда его не вставляй.

## Шаг 6. Привяжи приложение к кнопке меню бота

1. В @BotFather отправь `/mybots` и выбери своего бота.
2. Нажми **Bot Settings** → **Menu Button** → **Configure menu button**
   (в некоторых версиях — **Edit menu button URL**).
3. Отправь адрес приложения из шага 4: `https://<твой-логин>.github.io/<имя-репозитория>/`
   (обязательно с `https://` в начале).
4. Отправь название кнопки, например `Задачи`.

## Шаг 7. Открой из Telegram

1. Найди своего бота по username и нажми **Start**.
2. Слева от поля ввода появится кнопка **«Задачи»** — нажми её. Приложение развернётся на весь экран.
3. Плашки «Открыто вне Telegram» больше нет — задачи теперь сохраняются в облаке Telegram
   и будут на телефоне, планшете и компьютере.

Если кнопка не появилась — закрой и заново открой чат с ботом (иногда Telegram обновляет меню не сразу).

## Частые вопросы

**Видит ли кто-то мои задачи?** Нет. Облако Telegram хранит их отдельно для пары «ты + этот бот».
Другой человек, открывший того же бота, увидит свой пустой список.

**Сколько задач можно хранить?** Облако Telegram вмещает около 1000 записей. Когда задач станет больше 900,
во вкладке «Проекты» появится предупреждение с кнопкой «Очистить выполненные».

**Я поменял код — как обновить приложение?** Выполни в папке проекта:

```
git add .
git commit -m "Что поменял"
git push
```

Через пару минут обновление появится в боте (если нет — закрой и открой приложение заново).

**Workflow на вкладке Actions красный.** Открой его и посмотри шаг с ошибкой. Чаще всего забыли шаг 3
(в **Settings → Pages** поле Source должно быть **GitHub Actions**). Исправь и нажми **Re-run all jobs**.
